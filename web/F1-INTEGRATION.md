## 启动与 CORS

Node `v24.21.0`，在本工作树独立运行 `npm ci`，不用其他仓库的依赖。开发机 LAN 为 `192.168.0.200`，H5 源为 **`http://192.168.0.200:5173`**，首页为 `http://192.168.0.200:5173/#/`，API 基址为 **`http://192.168.0.200:4056/api/v1`**。这些是开发地址，跨设备可达性需用实习生设备复验。

```bash
cd web
npm ci
VITE_USE_MOCK=false VITE_API_BASE_URL=http://192.168.0.200:4056/api/v1 npm run dev:h5 -- --host 0.0.0.0 --port 5173 --strictPort
```

后端需精确允许上述 H5 源，以及 `Content-Type`、`X-Guest-Token` 和 `GET/POST/PUT/OPTIONS`。若改用 localhost、其他 LAN IP 或端口，必须同步后端 CORS；远端手机不能把 API 配成自己的 `127.0.0.1`。本轮 H5 运行终端：`term_920c8581-c32f-45b6-bd09-c60c6067fa4b`，交回后保持运行。

## 请求与恢复

- 首次读取首页记录会先领本浏览器游客，再 `GET /results?limit=1`；空 `items` 不阻止开测。同一运行实例的并发请求共用一次初始化，刷新从本机复用。身份按 API 基址隔离存储，不放 URL、构建变量或日志。
- 开测顺序为读取 `/quiz/versions/current` → 用返回的 `question_bank_version` 创建会话 → 验证服务端回显版本 → 缓存该会话完整题库与进度。答题页和刷新恢复只读该缓存，不再读取可能变化的当前题库。
- 每题保存成功才前进；交卷前用完整答案保存一次，再提交，成功后清除草稿并读取服务器结果。点击保存期间不重复写入；409 提示已提交并转阶段记录，不把重放当新测评。
- 旧草稿缺少原题库、版本不匹配或不属于当前 URL 会明确提示重开，不以新题库解释旧答案；只清草稿，不删除已有结果。
- 401/本机凭证过期明确提示失效，保留原身份失效标记，刷新也不会自动领新号，不静默重放写操作。首页显式确认新游客后才换号；新身份不会继承旧记录。清理浏览器站点数据也会丢失原身份，联调勿借此模拟刷新。

## 集成后复验

1. 使用独立浏览器配置文件 A 首次进入，Network 应只有一次 `POST /auth/guest` 201，随后 `/results` 200 空列表。关闭 Mock，不能以本地题库、缓存结果或 H5 HTTP 200 代替后端证据。
2. 开测记录题库版本和会话回显。答 3 题后刷新，题干、选项、题号与选择保持原会话，不出现新的 `/auth/guest`、`/quiz/sessions` 或当前题库请求。继续 12 题，保存 200、交卷 201、结果详情和列表 200。
3. 结果页「再测一次」回首页后开新会话，再答 12 题，生成不同结果 ID；刷新首页和结果页，原记录仍可读。首轮全第一选项预期 ESTJ，第二轮全第二选项预期 INFP（候选版本 `qb-v0.4-prototype-1`）。
4. 独立配置文件 B 创建独立游客，列表不含 A；拿 A 结果 ID 请求详情应 404。A 同一会话重复交卷应 409，服务重启后记录可读。
5. 让凭证失效或注入仅用于测试的无效凭证，写操作 401 后不应出现新游客请求或自动写入重放；刷新仍明确失效。用缺少原题库的旧草稿验证重开提示且历史保留。测试身份/答案只留专用开发库，不提交 token 或截图中的凭证。
6. F2 的删除、对比、自选、类型、分享预览不计入 F1 通过；分享页本地占位不算真实图片交付。
