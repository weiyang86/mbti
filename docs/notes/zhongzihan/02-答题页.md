## 调用接口

依据 `docs/api/接口文档-实习生版.md` 4.1–4.4：

| 时机 | 接口 | 前端封装 | 说明 |
|---|---|---|---|
| 进入页面 | `GET /api/v1/quiz/versions/current` | `getCurrentQuizVersion()` | 拿 12 题与 `question_bank_version` |
| 每次选择 | `PUT /api/v1/quiz/sessions/{id}/answers` | `updateQuizSessionAnswers()` | 单题增量落库，失败不阻塞答题 |
| 最后一题 | `PUT .../answers`（全集） | 同上 | 提交前用 12 题全集兜底一次 |
| 最后一题 | `POST /api/v1/quiz/sessions/{id}/submit` | `submitQuizSession()` | 生成结果快照，拿 `id` 跳结果页 |

## 字段核对

- [x] `dimension` 只有 `EI` / `SN` / `TF` / `JP`，映射为 E/I、S/N、T/F、J/P
- [x] `options` 固定两项，取 `option_id` 原样回传，不自行编码
- [x] `answers[]` 结构为 `{ question_id, option_id }`
- [x] 提交 body 含本机保存的 `life_stage` / `recent_status`（契约内可选字段）
- [x] 幂等：`409` 视为"已提交"，提示后跳阶段记录
- [ ] 鉴权头（`X-Guest-Token`）待真后端验证

## 结论

按原型 `quiz()` 还原：顶部演示条、`选择更接近日常的你 01 / 12`、细进度条、大号维度字母（E / I）、题干、A/B 选项卡、上一题、自动进入下一题、底部隐私说明。

**题库内容已替换为原型 `QUIZ` 的 12 道题**（题干与 A/B 选项逐字一致），例如第 1 题「忙完一周，你更想用哪种方式恢复电量？」。

交互实现：点选立即推进（本地状态优先），同时后台单题落库；第 12 题改为「全集 PUT → submit → 跳结果页」。提交时从本机读取测试入口保存的阶段信息，作为 `life_stage` / `recent_status` 传给接口。

本地 mock 验证：第 1 题题干与两个选项与原型一致，`E / I` 大字正常，点选后 `01 / 12 → 02 / 12`，控制台无 error。

## 卡点 / 需拍板

- **题库版本号未递增**：内容已换成原型题库，但 `question_bank_version` 仍是 `qb-v0.4-teach-1`。严格说内容变了应递增版本，否则历史快照会被误判为"同版本"。需 Remy 决定新版本号。
- **`409 already submitted` 的返回体不含 `result_id`**（文档 4.4 示例只有 `code` / `message` / `details`），前端无法跳到已生成的结果页，只能退到记录列表。需 Remy 确认 409 是否可带快照 id。
- **刷新丢进度**：没有「查询会话当前答案」的接口，刷新后本地 `answers` 丢失（`sessionId` 还在 URL 里）。本期不做恢复。
- **单题 PUT 失败被静默吞掉**，靠提交前全集 PUT 兜底。若 Remy 认为必须每题确认落库，这里要改成阻塞式并加失败重试。
- `life_stage` / `recent_status` 现在会提交中文标签（如「日常生活」），文档示例是 `campus` 这类英文值，取值规范待 Remy 定。
