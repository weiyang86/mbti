## 实现

- 新增 `ClientWorkspaceManagementController`、DTO、`ClientWorkspaceManagementService` 和客户权限目录常量，并注册到唯一 `ClientWorkspacesModule`；继续使用 `ClientAuthGuard`、`WorkspaceContextGuard`、现有 Prisma 服务和上下文权限。
- 路由：`GET/POST /api/client/workspaces`、`GET /api/client/workspaces/roles`、`GET/POST /api/client/workspaces/members`、`PATCH /api/client/workspaces/members/:membershipId/role`、`PATCH /api/client/workspaces/members/:membershipId/status`、`POST /api/client/workspaces/leave`、`PATCH /api/client/workspaces/details`。
- 新建 Workspace 在单事务内创建通用 OWNER/MEMBER、客户权限目录授权、创建者 OWNER Membership 与审计；创建使用 creator+idempotency key 重试保护。成员分页、增员/移除后重新加入、角色绑定、停用/恢复、成员离开与 Workspace 改名均限定在当前 Workspace。角色授予受操作者数据库权限子集限制；不能以客户端自报身份提升授权。
- 每个状态变更递增 membership `sessionVersion`，上下文 Guard 每请求查询数据库，因此下一请求即反映角色/成员状态变化。修改类请求核对 Web Origin 并拒绝 `sec-fetch-site: cross-site`。Workspace 并发 owner 变更以 PostgreSQL transaction advisory lock 串行化，并拒绝停用、降级或离开最后一个有效 OWNER。
- 审计和响应只写/返回必要的合成身份、资源、状态与关联信息；不记录密码、哈希或 Token。没有新增 API 页面、Prisma Schema、迁移或 seed 默认业务内容；只修正 runtime resolver 在启用异步运行时时必须执行已有 capability assertion 的行为，补足既有回归测试要求的 fail-closed。
