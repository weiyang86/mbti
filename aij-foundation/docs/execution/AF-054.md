## 实现

- 新增 `ClientWorkspacesModule`，只在客户认证能力启用时装配；复用现有 `ClientAuthModule`、`ClientAuthGuard` 与唯一 `PrismaService`。
- 新增 `GET /api/client/workspaces/context`，要求显式 `workspace.context.read` 元数据和 `WorkspaceContextGuard`，响应 `private, no-store`。没有权限元数据的 Workspace route 默认拒绝。
- 客户端用 `x-aij-workspace-id` 选择期望上下文；它不是授权证明。guard 先校验独立客户 cookie/JWT、issuer、audience、project/environment、DB session 与 MemberUser 状态，再由 service 用真实登录会员 ID 查询所选 workspace 的有效 membership、workspace 状态、role 状态以及 active role-permission/permission 行。
- 不缓存授权。Membership、Workspace、Role、grant 或 Permission 被停用/移除后，下一次请求即拒绝。查询只返回 workspace 标识/名称、role ID/code 和 active permission codes；忽略请求里的 `workspaceId` query、角色/权限提示和 member ID。
- 不信任 Admin token，也不使用 `ProjectProfile/OrganizationProfile` 作为客户租户边界。本卡不实现 Workspace CRUD、菜单/UI、邀请、默认 Workspace/权限 seed 或管理员 API。
- 仅为新建 AF-054 随机验收库和已有本地验证/Seed/运行时 allowlist 加入明确 AF-054 项；没有扩成通用任务通配规则。
