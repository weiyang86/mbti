## 实际实现与影响

- `aij-payment` 是查询 API、退款申请表与服务的唯一 owner。新增 `PaymentRefundRequestStatus`（仅 `pending_manual_review`）及 `PaymentRefundRequest`，以受限外键关联当前项目、支付订单、唯一 charge 交易和申请管理员；项目与订单、订单与 charge 采用复合 owner 约束，删除均为 `RESTRICT`。申请金额必须为正数，币种/指数/原因/幂等摘要与 fingerprint 有数据库检查；幂等唯一键限定项目与申请人。
- 新增 `/admin/payments/orders`、`/admin/payments/orders/:id`、`/admin/payments/refund-requests` 和 `/admin/payments/orders/:id/refund-requests`。Controller 使用现有 Admin JWT、严格 DTO、插件启用 Guard、独立 `admin.payment.read` / `admin.payment.refund.request` 权限及 `Cache-Control: no-store`；Service 通过服务端当前 ProjectProfile 过滤，不接收客户端 project/workspace 身份。
- 查询投影不含 Provider reference、credentialRef、回调 event/payload digest、签名或原始错误。退款申请在订单 advisory lock 中重新核对成功状态、唯一 charge、已退款/冲正账本及待审额度；相同幂等请求返回既有行，变更 fingerprint 或超额返回冲突。仅写 pending manual review 记录和既有去敏审计，不追加退款/冲正交易、不调用 Provider/SecretCenter。
- Web 新增 `/auth/payments` 页面，使用现有管理壳和后端权限结果显示订单、详情、人工申请列表与申请表；按钮同时按 `admin.payment.refund.request` 控制。真实 API/RBAC 仍独立强制授权。
- Schema / migration：新增 `20261101100000_payment_refund_request`；无业务订单以外的新业务表，无真实用户/资金数据迁移。Seed 仅新增两个支付管理权限代码。Controller/API、新页面、菜单可用性和 AuditLog 写入如上；日志只记录必要申请字段，不含原始幂等 key 或 Provider 密钥/引用。
