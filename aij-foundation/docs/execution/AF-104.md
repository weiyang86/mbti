## 范围与 owner

`aij-payment` 是 PaymentOrder/PaymentAttempt、服务端幂等和本卡读写权限的唯一 owner。业务插件通过 `PaymentPayableSource` 端口提供当前用户、workspace 和项目下的应付对象快照，金额/币种/小数位及 Provider/SecretRef 引用均由服务端返回。浏览器只传应付引用和幂等键；会员、workspace 和 ProjectProfile 身份从服务端会话及当前项目解析。客户端不能指定金额、币种、provider、workspace、member 或 project。

请求先持久化订单与 attempt，再以服务端订单号作为 Provider 稳定幂等键发起调用；调用结果只转成规范 attempt 状态。超时或无效返回保存为 `unknown` attempt + `pending` order，由 G18-03 查询/回调/对账处理，不在本卡自动确认付款或重试扣款。原始幂等键仅做 SHA-256 摘要，不落日志/响应/ledger；支付 API 按当前 workspace/member/project 限定读取。订单和 attempt 外键使用 RESTRICT。

生产 payable source、SecretRef credential resolver 和 Provider registry仍 fail-closed；本卡真实 HTTP 仅使用本仓库 test runtime 的合成 payable 与离线合成 Provider，不代表 live 收单、SecretCenter 生产接线或真实价格/资格 owner。金额价目与业务付款资格未被移入底座。

## 改动

- Schema/迁移：新增 `PaymentOrder`、`PaymentAttempt` 与状态枚举；项目、workspace membership 外键；作用域幂等/订单号/attempt 序号/provider reference 唯一键，金额/币种位数检查、状态索引及 RESTRICT 删除策略。
- API：客户 workspace 下单 `POST /api/client/payments/orders` 与本人/本 workspace 查询 `GET /api/client/payments/orders/:orderId`；RBAC/WorkspaceContextGuard、same-origin 写请求、PluginRoute 和 no-store 响应。
- 日志/数据：写去敏 `payment_order_requested` 审计；不写原始幂等键、Provider 凭据或 Provider 原始错误；真实支付/退款不触发。
- 运行时：aij-payment 进入静态 plugin catalog / host assembly；只有显式启用且实际 installation 为 enabled 时路由开放。非 test 环境没有 payable source、credential resolver 或 Provider 实例，失败闭合。
- 不新增页面、Seed 业务数据或客户/商户记录；不改 Web API 客户端。异步回调、交易事实、查询对账属于后续卡。
