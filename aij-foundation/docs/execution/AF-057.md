## 实现

- 新增 `/client/login` 与 `/client/workspaces` 页面。客户登录继续使用后端 HttpOnly 会话 Cookie；前端不持久化 Token 或密码。
- Workspace 选择列表只来自 `GET /api/client/workspaces`。每次选择都请求服务端 `/context`，后端仍按当前会话、有效成员关系及角色权限重新判定；浏览器中的 workspace ID 只是请求选择器。
- 页面只请求并展示服务端权限允许的角色、成员与操作。无 `workspace.member.read` 时不请求成员 API，并显示权限空态；只有服务端 context 包含管理权限时才显示写操作。API 仍是最终授权边界。
- 成员操作复用现有成员 CRUD API；角色选项另按服务端返回的权限子集过滤。切换账号先调用服务端 logout；工作区页对会话失效、重新聚焦及周期检查作出登录失效响应。
- API、Prisma Schema、迁移、数据库 owner 和管理员权限没有改动。新增 Web 端客户 API helper、测试 fixture/HTTP 回归和任务注册。构建输出使用被忽略的 `apps/web/.next-af057/`，避免覆盖占用中的 Web host 构建目录；ESLint 排除该独立缓存。
