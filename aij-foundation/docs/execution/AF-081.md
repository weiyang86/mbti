## 实现及影响

- Outbox 仅领取注册过的事件版本；插件事件还必须属于当前项目已启用插件。未知事件及停用插件事件保持 pending，不会被错误消费。
- 通知请求在调用方事务内写入 Outbox。相同幂等键和相同内容返回相同事件；复用该键提交不同内容返回冲突。
- Outbox 消费在同一事务内创建已有 RuntimeJob；RuntimeJob 是投递状态的唯一 owner。重试和退避沿用 Job 的 attempt/runAt/error 状态，Provider 幂等键稳定。
- Provider 实现必须由可信宿主模块注册；没有 Provider 时外部渠道失败闭合。插件只有 `ENABLED_PLUGINS` 显式启用时才装配，不会默认全部启动。
- Schema、迁移、表结构：未改变。新增受保护验收编号 allowlist 项，不新增迁移。
- 数据：最终真实集成库 `aij_foundation_af081_test_d5cc7e1f0298a9c6`，仅合成账号、Outbox/Job 与合成通知记录；保留在本地验收目录，不执行清库。最终断言证据：`.artifacts/af-081/integration/d5cc7e1f0298a9c6/notification-outbox.json`。
- API/页面/权限/审计：未新增通知路由、页面或权限项。真实 Nest 宿主在 OS 选择的 loopback 端口启动，集成夹具通过真实 HTTP 登录合成管理员；投递路径由本卡 Service/Outbox/Job owner 执行。没有调用外部 Provider。
- 不保存或输出 Provider 密钥、地址或异常原文。失败只存安全错误码。
