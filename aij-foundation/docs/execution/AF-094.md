## 实现与断言

新增真实 PostgreSQL/Nest HTTP 集成用例，使用本库按卡创建的隔离 acceptance DB 和内存中的离线合成 Provider：

1. Provider 第一次调用抛出含合成敏感片段的异常；同一 RuntimeJob 被持久化为 retry，attempt 1 Trace 记录 `provider_error`，错误正文和 prompt/凭据不落库。
2. 同一 Job 恢复为 attempt 2 后成功；两次调用共享 correlationId、traceId 不同；每个 attempt 只有一条 Trace；仅保存 Provider 回报的成本，不估算成本。
3. Prisma 断开并重连后，Trace/成本仍存在；重放相同幂等键返回同一 Job，不重复建 Job/Cost；冲突回执不能覆盖已记录成本。
4. 入队后的预算拒绝记录 `budget_denied`、无成本金额且不调用 Provider。

Schema、migration、公开 API 路由、页面和权限均未改变。真实数据库和 loopback Nest host 已运行；没有调用真实 Provider、模型、短信、邮件或其他付费服务。轻企源码及数据库未访问；未执行 reset/drop/down-v、清卷或停止无关进程。
