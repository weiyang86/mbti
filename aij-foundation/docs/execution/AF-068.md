## 实现

- `apps/api/src/plugin-runtime/plugin-lifecycle.service.ts`：唯一持久化生命周期 Service。依赖现有 `PluginInstallation`/`PluginOperation`、Prisma 和 `ManagementAccessService`，按当前活动项目解析安装归属；所有写入在受控事务内完成，并以项目/插件组合 advisory transaction lock 防止并发竞争。
- `apps/api/src/plugin-runtime/plugin-catalog.ts`：不可变静态可信注册目录，只允许经本机静态宿主显式登记的 Nest 模块和有效 owner；未知 code、无效注册和未登记版本拒绝。生产目录当前为空，不会默认启动任何插件。
- 支持 install、upgrade、enable、disable；安装和停用幂等，启用只接受已安装状态，升级仅允许到可信目录中更高版本，并要求先停用。每个真实状态变更写 `PluginOperation` 和去敏 `AuditLog`；权限复用既有 `ManagementAccessService`，缺少 `admin.plugin.manage` 返回拒绝且不落数据。
- `scripts/plugin-policy.cjs` 声明 `admin.plugin.manage` 元数据。`db:seed` 仅在显式 `--plugin-management` 时插入该定义，不授予角色；重复参数被拒绝。
- 沿用已有 Prisma Schema 和 initial migration；本卡不新增 Schema/migration。G11-04 才负责管理 API/HTTP 路由装配；本卡只交付可由后续 API owner 使用的 Service，不声明当前有管理员插件 API。
