## 实现

- 新增 `/api/admin/plugins` 管理入口：查看可信目录和安装状态、安装、升级、启用、停用、查看操作历史、为失败操作登记重试意图。控制器复用唯一 `PluginLifecycleService`、静态 `PluginCatalog`、已有 Prisma 生命周期模型、管理权限和审计；DTO 严格校验。没有动态加载任意路径、执行 Shell 或自动运行重试代码。
- 新增 `PluginRuntimeAccessService` 与 `PluginRoute(code)` 守卫。每次路由请求按当前项目读取已启用状态；状态检查和生命周期共用 project/plugin 事务 advisory lock。未启用/不存在的插件路由 fail closed。
- 插件任务在写入前校验当前项目安装为 enabled；worker claim 根据当前项目启用集合过滤。已 claim 但执行前插件已停用的任务不会调用 handler，会释放租约并记录固定 `PLUGIN_DISABLED` retry 状态。已进入执行的 handler 不会被强制中断。
- `SecretRefPort.resolveTrustedForPlugin` 仅在项目下存在该插件专属 `secretRef` 绑定、引用有效且安装启用时，从服务端 SecretStore 解析。停用后解析拒绝；HTTP 响应不含解析值。
- `AppModule` 的测试目录覆盖参数只允许 `APP_ENV=test` 且 `environment=test`，生产目录没有覆盖入口。没有在 production 导入运行时自动启动所有插件。

- 数据：正式校验通过独立随机 acceptance DB 迁移并写入合成项目、用户、角色、插件状态、操作、审计、runtime job 和 SecretRef 元数据。基础 `aij_foundation_test` 只用于 `db:check` 只读身份核验；不在该库写应用数据。验收 DB 未 reset/drop/清理。
- API：新增上文管理员生命周期端点；其授权依赖现有 `admin.plugin.manage` RBAC 权限。未知目录项、不可信版本、非法状态转移拒绝。
- 页面/菜单：无变化；本卡不提供插件管理页面，也不将隐藏菜单当作 API 授权。
- 权限/审计：匿名请求 401，普通管理员缺少能力时 403 且不写安装记录；生命周期成功变更和显式 retry intent 复用现有去敏审计 owner。
- 日志/凭据：错误正文、操作历史和审计不包含注入的数据库 URL/密码样式或 Secret 值；重试原因按安全类别返回。
- 生产限制：静态生产 catalog 目前为空；成功用例只使用测试专用合成 catalog，不构成真实插件安装、运行、许可证或发行授权证明。
