## 实现

- `plugin-manifest.ts` 对静态注册目录执行必需依赖存在性、声明版本范围兼容性、依赖环和确定性依赖优先顺序检查。可选依赖缺失可接受；目录存在时仍检查其版本范围。解析只生成顺序，不安装、导入或执行插件。
- `PluginCatalog` 提供依赖存在、依赖优先顺序与依赖者查询。
- 唯一生命周期 owner `PluginLifecycleService` 在事务中对相关插件按 code 排序加锁。安装/升级要求必需依赖已安装且版本兼容；启用要求必需依赖已启用；仍有已启用必需依赖者时拒绝停用；升级不能使已安装依赖者落到不兼容版本。缺失的可选依赖不阻塞。
- 不增加 Schema、migration、数据库业务字段、API 路由、页面或权限码；复用现有管理 API、RBAC、审计与 `PluginInstallation/PluginOperation` 数据 owner。测试只使用合成插件 catalog 与本库隔离 TEST acceptance database。
- 更新 [插件 manifest 契约](../development/PLUGIN_MANIFEST.md)。生产静态插件目录仍为空；本卡不表示有真实插件安装、发行授权或插件代码执行。
