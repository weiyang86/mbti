## 实现与影响

- 复用既有 `ClientAuthController/Service/Guard`、`PrismaService`、`ClientConsentRecord` 和 `AuditLog` owner；未新建平行身份/审计实现。
- 新增 `GET /api/client/auth/consents`：只返回当前已认证会员、服务端当前项目 namespace 中每种同意类型的最新记录，不返回旧 `legacy-unscoped` 或其他 namespace 数据。响应 `Cache-Control: no-store`。
- 新增 `PATCH /api/client/auth/consents`：必须通过客户会话 Guard 和同源检查；只允许 `ai_assistance`、`marketing` 两类；严格校验 `granted`、文本版本格式与 SHA-256 digest 格式，拒绝额外字段。`source` 与时间由服务端生成。
- 事务内使用 namespace/member/type advisory lock。相同状态、版本、digest 重复写入返回 `unchanged: true`，不增加历史行或审计；文本版本/digest 变化追加记录；撤回通过 `granted: false` 追加历史，读取只返回该类型最新状态。失败不会留下半条记录。
- 审计只保存关联 ID、固定路由和动作；不写 consent body、邮箱、IP、Cookie、token 或密码。没有账号注销、导出、注册或找回能力。
- Schema 增加 `ClientConsentRecord.namespace` 与按 namespace/member/type/time 的索引。迁移 `20261029010000_client_consent_namespace` 将旧无项目归属记录标为 `legacy-unscoped` 后设为必填，保证新项目不能读取这些记录。真实迁移只在新建的 AF-041 随机 test 验收库执行。
- 页面、管理员权限、Admin JWT 和管理员会话不变。未调用短信、邮件、付费服务或业务插件。

### 同意文本边界

请求中的版本号与 digest 表示客户端所展示文本的标识，API 会校验格式并持久化，但目前底座没有一份可作为法律文案权威的通用 consent 文本目录，因此 API 不声称独立验证客户端实际展示了哪段文案或构成法律合规证明。业务项目在真实收集同意前仍需提供其批准的版本/文案目录，并让受控 UI 使用对应版本和 digest。未复制轻企的品牌条款或业务文案。
