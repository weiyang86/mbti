## 实现与影响

- 下载 `GET /api/client/files/:id` 和删除 `DELETE /api/client/files/:id` 均由现有 `ClientAuthGuard` 保护。文件查询必须同时匹配本项目、客户 owner 类型、认证主体 ID、`workspaceId=null`、`pluginCode=null`、活动状态和未删除时间；猜到 ID 不构成授权。未拥有、跨项目、已删除或不存在均统一为 404。
- 删除写操作校验精确 Web Origin，并拒绝 `Sec-Fetch-Site: cross-site`。上传沿用同一同源检查。
- 下载从 LocalStorageAdapter 读取对象，并核对字节数与 SHA-256 元数据；成功响应只返回字节和 MIME，设 `Content-Disposition: attachment`、`Cache-Control: private, no-store`、`X-Content-Type-Options: nosniff`。本机路径和 object key 不返回给客户端。缺失对象被标记 `missing` 后返回 404；校验失败/存储故障不回显底层错误。
- 删除先以条件更新把活动行标为 `deleting`，再删除字节，最后软删除元数据（`status=deleted`、`deletedAt`）。并发/重复操作不能再次取得活动 owner 行。文件不存在时记录 `missing`，返回 404。
- 若对象删除后 PostgreSQL 拒绝最终 metadata 更新，服务恢复原字节、恢复 `active`/`deletedAt=null`，并返回固定去敏 503。恢复状态更新行数不为 1 时也失败闭合，不宣称恢复成功。
- Schema/migration/持久模型：无变更；使用既有 FileAsset 字段和唯一 Prisma client。数据库仅本库随机 AF-047 test 验收库写入合成客户及文件元数据，测试约束也只留在本卡自己的随机隔离库。没有页面、菜单、RBAC API 或审计 Schema 变化；没有读写轻企源码、数据库或上传路径。
- 本卡登记对 `runtime-environment.cjs`、migration/seed/auth fixture/readiness helper 增加 AF-047 本库随机验收任务白名单；verify 注册实际 HTTP/DB 测试、Prisma、构建和质量门禁。
