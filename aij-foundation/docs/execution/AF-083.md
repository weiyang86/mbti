## 本卡范围和差异

- 增加匿名 `POST /api/client/auth/register` 与严格 `ClientRegisterDto`。接受规范化邮箱、昵称和符合现有密码策略的密码；拒绝 DTO 外的 role、status、projectId、workspaceId、permissions 等字段。
- 服务以规范化邮箱做项目命名空间内 advisory-lock 去重，并由已有唯一约束兜底。新账号 bcrypt 哈希后以 `pending_verification` 状态创建；新账号和重复账号均返回相同 `202 { accepted: true }`，不暴露账号是否已存在。
- 注册使用现有 `ClientAuthRateBucket` 做按项目 HMAC 化的 IP 级请求限流；桶不存明文 IP。阈值压力测试不属于本卡，本次真实 DB 测试验证 HMAC 键持久化。
- 注册不签发 Cookie/JWT、不创建 Session/OneTimeToken/Consent、不建立 Workspace/管理员/项目权限；登录仍只允许 `active` 账号。验证令牌和通知投递留在 G5-02，找回流程留在后续卡。
- 审计仅记录通用 `registration_requested`、资源引用和 correlation ID，不记录邮箱、口令、IP 或 User-Agent。
- 为隔离验收增加 AF-083 到本库 migration/Seed/runtime/auth 测试保护 allowlist。没有改 Prisma Schema 或 migration 内容，不接触开发/共享/正式库。
