## 每项范围和可判定验收

<a id="opt-001"></a>
### OPT-001 修复租约接管与编排任务副作用准入

- 状态：待规划/未授权实现；P1；关联分析项：F01。
- 范围：执行前校验租约 owner/attempt，处理中幂等记录需有有效执行者；为外部调用定义 fencing、幂等键与不确定结果策略；复用现有 RuntimeJob/Idempotency。
- 验收：旧 claim 在新 owner 接管后不能进入 handler；两个独立连接/进程竞争只允许当前有效 owner 执行；崩溃前后和未知外部结果有明确重试/对账语义，不承诺无法证明的外部 exactly-once。
- 前置：无。适用条件：通用底座路线。

<a id="opt-002"></a>
### OPT-002 统一启动、管理与生命周期插件目录

- 状态：待规划/未授权实现；P1；关联分析项：F02。
- 范围：以一个可信注册源生成运行时装配、管理 catalog 和启动白名单；补齐 aij-ai 正常安装/启停入口。
- 验收：默认应用目录包含 AI/通知/支付；空库可经管理入口安装并启用 AI；未知插件拒绝，三处目录自动一致，无手工补数据库行。
- 前置：无。适用条件：通用底座路线。

<a id="opt-003"></a>
### OPT-003 统一 AI 全部知识接口与菜单的停用门禁

- 状态：待规划/未授权实现；P1；关联分析项：F03。
- 范围：覆盖手工创建、列表、编辑、查询、问答、评测及文件导入；读路径有统一启用检查，写路径与生命周期锁保持一致；区分启动 opt-in 与持久启用状态。
- 验收：插件停用后全部受管 API 与菜单按统一契约拒绝/隐藏；失败写入无副作用；恢复后允许；保留匿名、角色和跨 Workspace 拒绝路径。
- 前置：OPT-002。适用条件：通用底座路线。

<a id="opt-004"></a>
### OPT-004 修复运行时健康度与心跳时效

- 状态：待规划/未授权实现；P1；关联分析项：F04。

- 验收：心跳过期、poll 停滞、依赖故障能在管理运行时 readiness 中变为 degraded/503；恢复后转绿；DB ready 不等于 worker ready，disabled 模式按配置说明。

## 执行与证据要求

开卡先固定目标、owner、依赖和验收，再分配正式AF编号。每卡真实成功/拒绝/恢复路径、适用lint/typecheck/build/Prisma通过，记录未执行的人工与外部项；按既有负责人偏好逐卡提交推送。正式接收单独记录。

修复任务同时新增覆盖本次探针的产品回归，避免只通过卡片专用夹具。长期回归不应依赖历史HEAD或本机忽略的基线文件；多进程竞争要使用独立数据库连接/进程，不能用同一connection_limit=1客户端的Promise.all代替。

新增工具、Agent、检索或存储仍遵守既有身份/Workspace、SecretRef、AsyncRuntime、审计与成本唯一owner；不新建平行账本，不改原轻企仓库，不把模型输出当权限授予。

许可、渠道、真实凭据、真实外发/资金动作和正式部署由负责人决定；准备工作和本机隔离验证可先完成，外部等待时间不记作有效编码工时。
