## 批次授权与状态

**负责人批准明确批次 → Codex 顺序实现其卡片 → 每卡真实校验并修复 → 更新该卡执行记录/队列 → 按任务名本地提交该卡 → 批末 OWNER_CHECK_PENDING → 负责人统一检查/接收。** 负责人可一次批准多个明确批次，并明示批间连续权限和总预算；否则只执行当前批准批次。

- 默认最多 4 卡、12 有效工程小时；单卡预计超过 4 小时，先保留成果并拆卡。预算不是完成承诺。
- 批内卡片按依赖顺序连续执行，不逐卡等待人工确认；完成的卡记 `CODE_VERIFIED`。若负责人指定批末统一验收，则各卡人工验收字段标为 `DEFERRED_TO_BATCH_END`，不作为卡片继续执行的阻塞。
- 缺依赖、缺隔离环境、范围冲突、Writer 冲突、必须由负责人触发的真实外部接入或 Git/发布节点时暂停并交接。普通可修复错误在当前授权内修复并重跑。
- 后续不使用 Trea 复核；Codex 自查不能称为独立复核。历史 Trea/REVIEW_PENDING 仅作为历史状态保留。
- `verify:task` 只执行注册过的真实校验项，不会消费队列或自行写代码。当前没有无人值守编码执行器；30 分钟唤醒也保持暂停，不能把队列误当后台自动开发。

## 每批固定步骤

1. 读取根 `AGENTS.md`、`CURRENT_STATE.md`、本批 prompt、实际 package/注册表和相关 owner 文档；核对 branch、HEAD、status、diff，保存开始快照。
2. 只读原轻企源码；按 owner 定向复用本库已有实现。确认前置能力真实存在，未完成依赖记录阻塞，不复制第二个 Service 或假造 descriptor。
3. 对获批卡登记正式 AF 号与真实 `verify:task` 项；别名 `Gx-xx` 只是规划 ID。校验包括成功、拒绝、失败恢复；真实持久化/HTTP/DB/文件/队列实际运行。
4. 涉及代码跑适用 lint/typecheck；Schema 执行 Prisma validate/generate 和目标保护的迁移；Web/包改动构建受影响目标。保存参数数组、退出码、有效用例、断言和去敏证据。
5. 每卡校验通过后立即更新 `docs/execution/AF-编号.md` 与 `CODING_QUEUE.json` 中该卡的实际证据和状态；必要时更新 CURRENT_STATE。记录命令/退出码、断言、人工入口、遗留项与隔离保护状态。没有实际运行的服务不写成正在运行。
6. 每卡校验与文档/队列更新完成后，对本卡可安全分离的新增差异单独暂存并本地提交；提交标题逐字采用队列中的任务名称，AF 编号可写在提交正文；负责人明确要求该卡不提交时遵从其例外指令。提交包含本卡执行记录及本卡队列状态，不包含继承差异或其他卡差异。若同文件继承改动无法安全拆分，停止本卡提交并报告负责人；不得用 `git add -A`、`git add .` 或 `git commit -a` 把它们带入。
7. 单卡提交不等于验收或接收；批末仍为 `OWNER_CHECK_PENDING`。负责人保留 push、分支、PR、merge、tag、发行、部署与恢复续跑控制。停止本批 Writer；不自动开始未授权的下一批。

## 隔离与安全约束

- 轻企仓库和数据库只读；不复制源 `.env`、node_modules、历史迁移、客户数据或上传目录，不连接原数据库。
- 所有 DB 写入先核验目标；test 不回退 dev；不对现有库 reset/drop、不清空共享卷。服务启停先核验 PID/PPID/CWD/命令/birth，只操作本任务拥有的进程。
- 密钥只由负责人安全配置；不在证据、页面或日志输出密码、OTP、token、key、证书或 secret。自动校验不发真实短信、不扣款退款、不调用真实付费模型。
- 开发宿主端口保持 3655/3656，DB 保持 55432/55433；生成项目使用自己的 projectId、端口、issuer、Cookie 前缀、存储和数据库。
- 许可、发行渠道、支持平台和实际生产部署继续由负责人裁定；本地 pack/install 验证不等于授权发布。
