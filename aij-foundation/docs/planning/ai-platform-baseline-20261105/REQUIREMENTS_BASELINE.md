# AIJ 通用 AI 底座正式需求基线

版本 AIJ-REQ-20261105-R1；日期 2026-11-05；适用仓库 aij-foundation。负责人已在本次会话逐轮确认产品目标，并明确接受切换计费、退款和恢复保留建议。本文件是本轮获准形成的需求基线，文件版审阅为 OWNER_REVIEW_PENDING。需求确认不改变历史 AF 卡验收、发布许可或工程实现状态。

AIJ 面向内部及第三方开发者，交付可独立部署的通用 AI 应用平台。产品提供管理后台、普通用户工作台和 API/SDK；各行业通过独立业务插件组合通用能力。论文、维修是验证通用性的业务样例，完整业务流程、论文规则、门店、工单、商品、行业订单和权益由各业务 owner 持有。

源码对照点为 `dev@b8eb9c2ecc4cca749c5dd1d38dc43489cda3a01c`。当前代码仍为模块化单体 Alpha；[源码复用与缺口](SOURCE_GAP_ANALYSIS.md)说明已有资产，[阶段与验收](DELIVERY_AND_ACCEPTANCE.md)说明交付顺序；[机读追溯表](traceability.json)连接需求、源文件、阶段和验收场景。需求编号用于本次产品追溯，不是正式 AF 编号。

## 一 产品范围与交付边界

1. 每个产品独立安装、数据库、凭据、会话命名空间和存储，不共享业务用户或运行数据。两层市场只分发包、元数据和授权，不取得消费者业务库。
2. 新建项目默认完整 AI 标准版，同时保留基础后台和自定义组合。默认入口包括管理员、用户、附件、模型、Agent、Skill、知识、编排和插件管理。已实现但未配置显示待配置；未实现标未交付，不能用占位菜单代替实现。启停、缺依赖及故障分别显示。
3. 首批部署环境为 Linux 单机私有化；多节点、高可用、离线环境、语音和视频未列为首批承诺，也不因菜单/接口预留而视为已交付。
4. 首批模型厂商为 DeepSeek 和阿里云模型平台，存储为本地及七牛。阿里云具体以百炼为暂定映射，地域、账号和模型 ID 按 O01 核定；不能把任意 compatible 地址配置视为已实测厂商适配。
5. 论文产品首期个人使用、后续团队；维修产品支持多个独立商家。通用个人/组织/成员能力进入底座，门店、订单等仍由行业插件维护。

## 四 已接受的默认规则

### 密钥 付款来源与切换

- 运行前显示模型、凭据归属、付款来源及预算。跨自带密钥与平台额度默认关闭；付款方显式授权候选范围和单任务/每日上限后才可切换。组织和个人分别授权，不因切换空间转移已运行任务付款方。
- 单步骤总尝试数最多3次、跨模型切换最多1次，全部尝试共享预算；为在途请求预占额度，预算不足不启动下一调用。
- 结果未知先核对，不能把超时当成未执行；涉及通知、支付或其他外部写入，核实原操作后才重试。向量模型切换按索引迁移处理。
- 用户脚本运行受隔离与资源限制，通过受控工具使用模型，不获得产品/其他用户密钥；外部文件、网页和包内容不授予额外工具权限。

### 费用与退款

上游成本真值仍归 aij-ai 执行/Trace；对客售价、付款账户和价格版本另有明确归属，以唯一任务/调用关联。已有预算预留不是现金钱包。对客计量/额度若新增实现，必须引用现有成本真值，而不是复制第二套厂商成本账。

采用预占、结算、释放差额，例如预占10元、可计费3元时实扣3元并释放7元。actual usage优先取厂商回执并做账单核对；缺失计量先待核对，不按零成本或猜测加扣。按量商品与按成果商品分别公示计费规则。

| 情形 | 默认处理 |
| --- | --- |
| 未执行即取消 | 全部释放预占 |
| 平台故障未交付可用成果 | 退对应费用，平台承担已产生的上游成本 |
| 用户中途取消 | 按公示规则结算已完成部分，释放未执行部分 |
| BYOK | 厂商费用由用户与厂商结算，产品另收计算/存储/服务费须预先展示 |
| 充值退款 | 核算未消费的可退实付余额并向原渠道申请，赠额单独处理 |
| 退款及调整 | 追加流水；申请/处理中/成功/失败分别记录，渠道核实后才确认成功 |
| 订阅续费 | 独立续费授权、到期提醒和关闭入口；当前账期退款按公示规则及适用要求处理 |

微信、支付宝和抖音分别核定渠道能力。订阅、优惠、分账和结算的通用抽象不构成所有渠道均可直接支持的承诺。抖音小程序交易仅是首条接入建议，具体产品/类目仍待 O02；未配置商户只显示待配置，不伪造真实收款。

### 恢复与保留

恢复先在隔离目标重建，检查数据库、对象文件、配置及依赖，展示差异后再应用。组织恢复只影响目标组织相关写入/任务，其他组织继续使用。资源默认成为副本或新版本；恢复点之后的修改须显式选择保留当前、恢复副本或逐项替换，不能静默覆盖。

支付、退款、结算、消费流水和审计保留事实历史；整实例灾备后先对账再开放有关操作。恢复不自动重发通知/扣款/任务，不复活撤销的凭据、会话、权限或已删除记忆。当前成员关系与授权须重新验证。

| 内容 | 已接受的默认期限 |
| --- | --- |
| 已验证近期恢复点 | 近7天，目标间隔不超过15分钟；数据库与附件未共同验证的点不可选 |
| 日备份 / 月备份 | 30天 / 12个月 |
| 自动草稿 / 手工保存版本 | 30天 / 90天，可由产品延长 |
| 发布版本 | 有有效安装、购买授权、任务引用时保留；下架后至少180天，依赖未结束不清理 |
| 删除资源回收站 | 30天；备份随其周期到期清理，恢复仍执行删除/撤权标记 |

这不是已经达到的RPO/SLA。容量、成本和恢复耗时需实测；财务/审计另定保留策略。现有知识问答/Run的7天正文清理与自动草稿是不同数据类别，不能直接延长或停用既有清理；问答/运行原文期按 O06 明确。

| aij-ai | 模型目录/Agent/Skill/知识/记忆及执行Trace；新增能力可拆包，不能复制执行或实际成本真值 |
| aij-payment / aij-notification | 分别拥有支付轨道/回调/退款/对账和投递真值；扩展商户/渠道适配 |
| 业务及市场 | 行业订单、商品、价格、权益和市场授权；经受控端口引用支付、文件、任务和AI |
| 待设计的对客计量与运维 | 额度/收费、恢复计划和执行记录各选唯一owner；不得以历史预算表当钱包，或把升级器做成任意命令入口 |

保持manifest与锁文件核验的现有技术栈，不借此次升级顺带升级框架。保留来源与许可证；现有UNLICENSED/All Rights Reserved不推定公开许可。AIJ市场与第三方开发目标不自动授权公开发包、部署、push或改真实业务仓。
