01 / PRODUCT THESIS

用好看的图吸引，用自己的记录留下。

MBTI搭子面向对 16 型人格感兴趣、希望用漂亮形象表达自己的年轻成年人。第一笔消费围绕“发一条有辨识度的朋友圈”，后续回访围绕“留住阶段记录、看看答案是否不同”，同时提供自愿的名片与联系方式交换。

01

测：明确的品类入口

12 道原创固定选择题，约 2 分钟。提供趣味类型倾向与选择依据；已知类型可直接做卡。没有自由问答或在线聊天。

02

晒：看得见的消费场景

朋友圈海报、同款头像、见面名片先预览，再购买。¥9.9 交付图片与配文套装；说明书是可保存的附加价值。

03

换：有边界的轻社交

按同型和兴趣发现名片；名片交换与联系方式交换分两步。付费只买视觉作品，不购买他人的联系方式。

主张：“把我的 MBTI，做成一张想发朋友圈的图。”
不同人的昵称、兴趣、宣言、照片与视觉风格共同构成差异化。只有换四个字母的模板，不能当作深度个性化来宣传。

工作名称：MBTI搭子

MBTI 直接提示测试品类，“搭子”提示交换与相处场景。统一副标题为“16 型人格测试 · 专属名片 · 同频交换”。名称仍需在投入运营前核对商标、平台名称与近似品牌；本产品不是官方 MBTI 测评，不暗示品牌授权或科学诊断。

统一一个品牌：微信、小红书、抖音与公众号使用同一名称与视觉。首阶段以一个团队、一个后台交付；多个风格作为商品内选项。

商业判断，要靠真实订单。

文章中“9.9 元、2.5 万单”为作者自述，不能据此预测本项目销量或利润。V0.4 的假设是：完整成图和具体使用场景比抽象的“认识自己”更容易解释价值。是否提高转化，需要用真实访问、付款、退款和分享回流验证。

02 / MOBILE & CHANNELS

手机是主场，平台是入口。

V0.4 采用单列手机界面、底部导航、底部主操作和半屏选择器。电脑打开也展示手机应用；左侧渠道切换用于评审。当前交付是 HTML 交互原型，四种渠道皮肤用于验证流程，不代表已经生成四个平台的小程序安装包或完成审核。

第一条路径 · 快速做卡

“我已经知道 MBTI。”

选类型与兴趣 → 场景预览 → 选套装 → 保存分享。用户选择的类型明确标注来源；无需完成测试也能使用基础名片与交换功能。

第二条路径 · 先测一测

“我还不知道自己的类型。”

每屏一道固定选择题 → 12 题进度 → 免费倾向结果 → 朋友圈成图 → 购买套装。没有自由输入回答；可以返回修改，也可以重新测试。

05 / STAGE RECORDS & RETENTION

不要求每次变一种类型，也有回来看的价值。

V0.4 将“我的轨迹”作为底部主入口。用户留下的是多次真实作答快照；结果变与不变都值得记录。当前 12 题为原创趣味问卷，能比较回答差异，尚不能科学确认人格特质已经改变。

01 · 留下起点

每次完成，新增一份记录。

保存完成时间、12 个答案、四维题数、类型结果和版本。生活阶段与近期状态选填，仅作为回看背景。重复进入结果页不生成重复记录。

02 · 同条件复测

固定核心题目与回顾时间窗。

统一按最近四周通常状态作答。固定题目、选项映射和计分规则，保证前后可核对。可以返回改未完成答案，完成后的历史快照不随新测试变化。

03 · 看具体差别

类型相同，也看得见回答变化。

任选两次同版本结果，比较四维题数与不同答案；图表不展示虚构的百分比成长。相同答案显示“稳定”，短时间复测提示可能只是作答波动。

04 · 自愿分享与回访

把变化留成一张图。

基础阶段图免费保存。仅展示选中的两个结果，昵称与阶段默认不带入，近期状态和原始答案永不进入分享图。可设置本机复测计划、导出日历事项。

怎样实现长期价值与收入

免费保留复测、历史与基础对比。先建立“这里保存着不同阶段的我”的使用价值。当前 9.9 / 19.9 继续围绕视觉交付收费；后续只有在确实新增交付时，再测试季度视觉主题或年度阶段册。不能靠隐藏历史、故意变换测试结果或频繁提醒制造复购。

留存假设：首次测试留下基线 → 生活阶段变化或自定日期回访 → 新结果与旧结果对比 → 自愿更新名片 / 分享图 → 更长的个人档案。
这个循环值得验证，但“增加历史功能”不等于已经证明产品常青。先看 30 / 90 天真实复测与对比行为。

正式开发必须保留的契约

  • assessment_snapshot 至少包含 user_id、assessment_id、completed_at、test_version、scoring_version、time_window、answers、dimension_counts、type、origin；记录创建要幂等。
  • 生活阶段、近期状态、原始答案、公开名片、分享图白名单分别管理；服务端逐用户授权，默认历史私密。
  • 比较只允许题目、计分与时间窗一致的快照。题库改版后新建版本；没有验证过的换算不能拼成同一趋势线。
  • 保存后不覆盖旧答案；修改当前名片不反向改变历史。删除快照后相应对比不可再用，不恢复已删除内容。
  • 原型中的 12 题只用于体验。若正式产品要宣称可靠地测量长期变化，应引入合适的专业评估与授权量表，验证重测信度、效度和变化的可解释性，不能把正式 MBTI 的研究指标套到本问卷上。
  • 日历由用户自行导入；未来接入平台订阅提醒时另行取得授权，并支持取消。不给未授权用户发促销提醒。
表述边界参考（2026-10-22 查阅）：The Myers-Briggs Company · MBTI Facts，第 9–10、13 节。该出版方区分官方评估与网络问卷，并指出某些生活事件可能影响作答结果；其类型理论也不同于连续人格特质量表。本项目据此将功能命名为“阶段记录 / 结果对比”，不把复测差异直接宣称为人格改变。
06 / STANDARD OPERATING PROCEDURES

每一次付款与交换，都有明确步骤。

以下是从原型到正式试运营的执行要求。角色可由小团队兼任；原型按钮演示不能替代服务端授权、真实支付或正式审核。

SOP 01 固定选择题 → 可解释的结果 产品 / 内容
  1. 固定 12 道原创题，每个维度 3 道，统一回顾最近四周。版本、选项与映射规则同时保存；完成后新增快照，重测不覆盖历史。
  2. 类型结果由预先定义的规则决定；图像模型不判断人格，用户照片不参与计分。
  3. 自选类型和测试结果分别标记；展示选择倾向，不生成伪精度的准确率、心智阶位或“官方认证”。
  4. 公开宣言使用可审核的预设句；分享配文在用户本地编辑。昵称与未来上传内容仍走必要检测。
验收：相同题目版本与答案得到相同结果；无自由问答入口；免费结果无需购买即可查看。
SOP 02 场景预览 → 晒图套装成交 产品 / 设计 / 增长
  1. 先展示朋友圈、头像、见面三种成品用途，直接呈现用户将得到的图，避免只列抽象的报告功能。
  2. 9.9 套装逐项说明海报、头像、说明卡、配文；19.9 的本人照片能力在接入前明确是演示，不当作真实效果售卖。
  3. 固定价格 9.9，先比较“抽象说明文案”和“场景成图预览”的支付率；保持渠道、受众与权益一致，不同时改多个变量。
  4. 素材用实际交付作品，不做虚构限时、销量、买家好评。记录支付、交付、下载、退款和可归因新访客。
验收：用户付款前能说清买到了什么；提高支付的同时观察退款与满意度，不能只追点击。
SOP 03 照片授权 → 套装生成与交付 技术 / AI / 设计
  1. 上传前说明用途、保存期限与使用权，展示明确的虚构样例；照片与原始资料默认不公开。
  2. 以订单、授权、样式与配额建立异步任务；照片链接设访问限制，技术失败恢复额度。
  3. 先校验生成图与文字，再用确定性排版输出海报、头像、说明卡；保留适用的 AI 内容标识。
  4. 成功后可重复查看与下载。成图不满意按公开规则处理重试或退款，不把效果归因于用户“人格有问题”。
验收：当前原型只预览上传照片；真实上线须证明模型确实使用授权照片并达到商品样例标准。
SOP 04 名片申请 → 双方交换 产品 / 后端
  1. 推荐基于用户主动填写的类型与兴趣，解释推荐依据；不编造恋爱成功率或科学匹配指数。
  2. 请求状态包含待确认、已同意、已拒绝和已撤销；未同意时只显示用户主动公开的名片字段。
  3. 正式版由真实接收者确认，不能由申请者替对方同意；原型显式提供“模拟对方同意 / 拒绝”供评审。
  4. 设置申请频率、拒绝后冷却、拉黑与举报。撤销或拉黑同步撤销联系方式授权；解除拉黑不自动恢复授权。
验收：免费用户能交换名片；没有聊天或任意附言；未同意者不会收到另一人的私密字段。
SOP 05 微信 / QQ / 电话 → 单独授权 后端 / 产品
  1. 名片已互换后，申请者选择要提供的具体渠道，确认指定接收者；另一方选择自己的渠道并单独同意。
  2. 服务端按双方、渠道与有效期校验授权，只返回允许展示的字段；不能把全量联系方式发给前端再用遮罩隐藏。
  3. 联系方式加密存储、访问审计，禁止写明文日志、公共海报、分享 URL、埋点或本地长期缓存。
  4. 允许拒绝、撤销、拉黑、修改或删除。修改号码时使旧授权失效；撤销仅阻止后续访问，无法收回对方已复制或截屏的数据。
  5. 原型联系方式只在本页内存保存，刷新即清除；对方展示值是不可用于实际联系的演示占位。
验收：付费不产生联系授权；未确认、拒绝、撤销与拉黑均不返回联系方式；只选择微信时不泄露 QQ 或电话。
SOP 06 同型雷达 → 聚合人数 产品 / 数据 / 后端
  1. 首次开启时单独说明用途并征求同意，拒绝也能使用测试、晒图与名片交换。当前原型仅模拟，不调用设备定位。
  2. 正式版先评估本地用户密度；仅统计自愿进入统计范围的活跃用户，明确时间窗，不把所有历史账户当作附近的人。
  3. 只输出粗粒度网格聚合人数；低于内部阈值（试行 k≥10）隐藏，计数分桶 / 缓存，限制移动位置与重复查询频率。
  4. 防止通过连续切换半径、边界或时间差推断个人位置；不显示个人距离、地图点、行走轨迹或精确名单。
  5. 关闭授权后停止后续定位处理并按声明期限清理；人数不足先显示“暂不展示”，不编造用户来装热闹。
验收：授权开关、低人数隐藏与防差分机制经验证后才接入；雷达不是首期付费承诺，mock 数字必须醒目标明。
SOP 07 真实交付 → 内容与传播 运营 / 项目负责人
  1. 围绕“我的 MBTI 朋友圈封面”“头像与名片一套”“第一次见面如何介绍我”制作原创素材。
  2. 与校园或生活方式创作者先做小规模真实体验，约定素材授权、费用和有效订单口径；不伪装买家。
  3. 各平台使用获准的分享与交易方式；不要默认要求用户发布，也不以强制分享解锁已购物品。
  4. 分享按钮点击、图片保存、草稿保存与真正带来新访问分别记账；排除自点、测试与重复用户。
验收：复盘付费净收入、每单成本与新客来源；在可重复获客前暂缓课程、代理和多品牌矩阵。
SOP 08 支付、审核与异常处理 客服 / 技术 / 负责人
  1. 服务端创建订单与金额、校验支付回调并幂等授予权益；测试与真实订单隔离，退款同步权益和配额。
  2. 对生成失败、支付不到账、效果不符设工单与升级负责人，保存原因码与处理记录。
  3. 昵称、照片、联系人字段、公开名片仍需适用内容处理，提供举报、拉黑、封禁与申诉。
  4. 发布前核对实际业务、渠道与主体对应的准入、数据、AI 标识和交易要求；声明并验证资料保存、撤销与删除流程。
验收：有真实客服入口和异常处理负责人；前端隐藏字段时接口也不泄露；测试退款、授权撤销与删除均可复现。
07 / DELIVERY PLAN

先完成付费交付，再开放真实交换。

按功能门槛推进，以下天数是资源齐备时的排期草案；平台准入和审核单独跟进。首期只做一个品牌与一条可追踪的交易链路。

D1–D3

锁定名称、场景与种子样本

产品 + 设计：核对工作名称，访谈 20 位目标用户；比较三种使用场景的吸引力，确认 9.9 的四件实际交付。

D4–D8

上线可交付的测试与晒图核心

全栈 + AI：固定题目、账号、支付沙箱、任务队列、权益、图片导出；本人照片能力未验收则先不上架对应商品。

D9–D12

打通名片申请与联系方式授权

后端 + 前端：实现真实双方状态机、渠道字段隔离、撤销、拉黑、频控与举报；以受控测试账户做越权验证。

D13–D15

真机验收与小范围受控体验

产品 + 测试 + 客服：验证生成、保存、支付、恢复、删除与售后。审核未完成时只做测试；雷达保持 mock 或关闭。

随后 14 天

单渠道付费实验，按周复盘

运营 + 负责人：预设预算上限；对照场景预览的支付、退款和传播回流。用户密度足够且隐私方案验证后再单独试行定位聚合。

10 / NEXT DECISION

三个方向，有先后才有胜率。

现在 · 自营验证

一个品牌，一个场景。

先卖出并交付好一份产品。观察谁购买、为什么分享、为什么退款。视觉风格作为同产品内选项，无需先建多个平台。

验证后 · 工具化

把可重复的流程变成工具。

当自营获客与交付可稳定复现，再考虑工具授权与运营培训。明确实际支持范围，不用收入截图承诺学员收益。

更后面 · 社交深化

用真实回访决定社交投入。

先受控试行双向名片与联系方式交换，观察真实回访。雷达的真实定位聚合在用户密度、授权和防推断方案验收后单独开放。

THIS WEEK / 本周可以开始

拿原型去观察，而不只是问“喜不喜欢”。

约 10–20 位目标用户，观察他们能否独立完成流程；请他们指出愿意付费的具体部分、最想修改的地方，以及会不会真的把名片发给某位朋友。原型中的支付点击只代表兴趣，真实付费仍需后续验证。
